1. Modern OpenGL & SPIR-V Shader Pipeline

Low-Overhead Pipeline

Structured around explicit memory buffers and state change minimization. Utilizes Uniform Buffer Objects (UBOs) explicitly aligned to std140 rules to cleanly share camera matrices and material parameters across shaders.

// SPIR-V Binary Compilation & Loading (Offline GLSL/HLSL Pipeline)
GLuint vs = glCreateShader(GL_VERTEX_SHADER);
glShaderBinary(1, &vs, GL_SHADER_BINARY_FORMAT_SPIR_V, spirvData, size);
glSpecializeShader(vs, "VSMain", 0, nullptr, nullptr);
  • Offline Execution: Uses glslangvalidator to bypass runtime GLSL parsing.
  • API Readiness: SPIR-V intermediate bytecode eases future migration to Vulkan.

2. Sol3 & Lua Dynamic Scripting Architecture

LuaJIT Engine Binding

Decouples gameplay logic from C++ core binaries. Exposes engine transforms, asset loading, hardware inputs, and camera hooks directly into isolated Lua state environments.

3. Portable 'Zero-Install' Environment

Automation

Engineered to eliminate bulky IDE dependencies. A single idempotent PowerShell script provisions w64devkit (GCC/Make), resolves pre-compiled dependencies (SDL3, GLM, Sol3), and setups a deterministic environment on clean Windows machines.

01 Automated directory structure mapping
02 Conditional dependency fetching (SDL3, GLM, ImGui)
03 Standalone binary linking with GCC/MinGW
Asset Injection Pipeline

Features native support for glTF 2.0 (.gltf/.glb) via lightweight cgltf header parsing, alongside Wavefront OBJ legacy support.

Key Engineering Insights & Takeaways

Low-Level Graphics & Hardware API Mental Model Progressing from raw OpenGL 3.3 to 4.6 explicit state binding provided deep clarity on GPU driver interaction, manual function pointer loading via GLAD, and memory alignment—laying direct groundwork for Vulkan development.
Compilation & Build System Demystification Working without IDE abstractions enabled a granular understanding of linkers, include paths, and compiler flags (gcc/cl). This knowledge translates directly to optimizing complex commercial builds (Unreal Engine / Unity).
Cross-Engine Optimization Mindset Understanding exact draw-call costs, state changes, and memory layouts informs better asset structuring and rendering decisions inside commercial engines.
